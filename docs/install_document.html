ferris-watch Online Installation Guide

This document provides instructions for installing the ferris-watch application on Windows, macOS, and Linux systems. ferris-watch is designed to collect and expose JVM metrics.

Important: This application requires administrative privileges for installation to ensure proper system integration and auto-start functionality.

System Requirements

  • Operating System: Windows 10/11, macOS, or Linux (with systemd support recommended).
  • Java Development Kit (JDK): A compatible JDK (version 8 or higher) must be installed and configured on your system. Ensure the JAVA_HOME environment variable is set correctly if you are on macOS/Linux and wish to include it in the service configuration.
  • Network: Internet access is required for initial download and automatic updates.

Installation Steps

1. Download the Executable

Download the latest version of the JVM Exporter executable for your operating system from the official release page or the provided download link.

Example download links (replace with actual links):

  • ferris-watch for Windows (.exe)
  • ferris-watch for macOS
  • ferris-watch for Linux

2. Install the Application

For Windows Users:

  1. Locate the downloaded install.bat file.
  2. Run the installer: Double-click on the install.bat file to execute it.
  3. The ferris-watch program will automatically handle the installation, including setting itself up for auto-start and checking for updates.
  4. A command prompt window may briefly appear during the installation process.
  5. Once the installation is complete, the ferris-watch application should be running in the background.

For macOS and Linux Users:

  1. Locate the downloaded executable file (e.g., ferris-watch).
  2. Open a terminal.
  3. Navigate to the directory where you downloaded the executable.
  4. Make the executable runnable (if necessary): 
    chmod +x ferris-watch
  5. Run the application with the auto-start flag: 
    ./ferris-watch --auto-start

    This command will start the ferris-watch application, configure it for auto-start, and enable automatic update checks.

  6. Once executed, the ferris-watch application should be running and configured to start automatically with your system.

Verification

To verify that ferris-watch is running correctly:

  • For Windows:
    • Open Task Manager and look for ferris-watch.exe in the "Details" tab.
    • Check if the application is listening on its default port (e.g., 29090) by opening a web browser and navigating to http://localhost:29090/metrics. You should see Prometheus metrics output.
  • For macOS/Linux:
    • Check the status of the systemd service: 
      sudo systemctl status ferris-watch.service

      It should show "active (running)".

    • Check if the application is listening on its default port (e.g., 29090) by opening a web browser and navigating to http://localhost:29090/metrics. You should see Prometheus metrics output.

Updating the Application

The ferris-watch application includes an automatic update mechanism:

  • The application periodically checks for new versions from a configured update service.
  • If a new version is available, it will be downloaded to a temporary location.
  • The application will then attempt to replace the running executable with the new version and restart itself. In some cases, manual intervention (e.g., restarting the application or replacing the executable) might be required if the automated process cannot complete due to permissions or file locks.

Troubleshooting

  • "Access Denied" or Permissions Errors: Ensure you are running the installer with administrative privileges (Right-click "Run as administrator" on Windows, or use sudo on macOS/Linux).
  • Application Not Starting:
    • Check system logs for errors (Event Viewer on Windows, journalctl -u ferris-watch.service on Linux).
    • Verify that your JDK is correctly installed and JAVA_HOME is set (if applicable).
  • Port 29090 in Use: If another application is using port 29090, the installer on Windows will attempt to kill it. On other systems, you might need to manually stop the conflicting process or configure ferris-watch to use a different port (refer to configuration documentation).
